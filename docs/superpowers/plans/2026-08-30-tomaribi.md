## T1. キャンプ場データの型と最初の実データ

spec 4節の形で `src/lib/data/campsites.js` を作る。**まず10件**、`verified: true` と `source` 付きで。奥多摩・檜原・青梅あきる野・湾岸から取る。

- (a) テスト: `campsites.test.js` — 全件が必須キーを持つ / `id` が一意 / lat,lon が東京都の範囲（lat 24〜36, lon 138〜154。島しょを含むため広い）/ `verified:true` なら `source` が http で始まる / `transit` が非 null なら `legs` が1つ以上 / `season` の月日が `MM-DD` 形式
- (b) 実装: データ10件
- (c) `pnpm test`
- コミット: `data: キャンプ場データの型と最初の10件`

## T2. `format.js` — 表示整形

料金（`per_person` / `per_site` の別）、所要時間（分 → 「1時間45分」）、距離、営業期間の人間向け表記。

- (a) テスト: 0分・60分ちょうど・端数、料金が min===max のとき「1,500円」・違うとき「1,000〜2,000円」、通年（`season: null`）→「通年」
- (b) 実装
- コミット: `lib: 料金と所要時間の表示整形`

## T3. `access.js` — アクセス判定

- `reachableWithoutCar(site)` → boolean
- `accessBand(site, { hasCar })` → `'near' | 'mid' | 'far'`（車: 〜60/〜120/それ以上 分。公共交通: 〜90/〜150/それ以上 分）
- `arrivalMargin(site, departHour)` → 最終到着時刻に対する余裕（分）。`transit` が null なら null
- (a) テスト: `transit: null` の site が `reachableWithoutCar === false`、境界（ちょうど60分・120分）、遅い出発で余裕が負になる、島しょ（`transit.minutes` が 400 超）が `far`
- (b) 実装
- コミット: `lib: アクセス判定（車なし可否・所要帯・到着余裕）`

## T4. `filter.js` — ハード制約による絞り込み

spec 3.1 の失格表をそのまま実装。`disqualify(site, criteria)` は**失格理由の配列**を返す（空配列 = 通過）。`filterSites(sites, criteria)` は通過したものだけ返す。

- (a) テスト: 失格表の**8行それぞれについて**、該当する site が落ちること・しない site が通ること。複数該当時に理由が複数返ること。空の criteria では全件通ること
- (b) 実装
- (c) `pnpm test`
- コミット: `lib: ハード制約による絞り込み`

## T5. `score.js` — 重み付きスコアと寄与

`scoreSite(site, criteria)` → `{ total, contributions: [{ axis, raw, weight, points, label }] }`。
軸は spec 3.1 の6つ。重みは criteria 依存で1つのテーブルに集約（`weightsFor(criteria)`）。

- (a) テスト:
  - 全軸の素点が 0..1 に収まる（全キャンプ場 × 代表 criteria で総当たり）
  - `total` が寄与の和と一致する
  - 車なし criteria でアクセス重みが車あり時より大きい
  - 同一 site で「焚き火したい」criteria のほうが焚き火軸の points が大きい
  - **落ちうる側の assert**: 全キャンプ場のスコアが同値になる criteria が無い
- (b) 実装
- コミット: `lib: 適合度スコアと寄与の記録`

## T6. `reasons.js` — 理由文

`reasonsFor(contributions)` → `{ plus: string[], minus: string[] }`。加点上位3・減点上位2。寄与の種類ごとにテンプレ1つ。

- (a) テスト: 加点が3件を超えても3件で切る / 減点が無ければ `minus` が空 / 同じ入力で同じ文（決定論）/ **全軸のテンプレが存在する**（軸名の集合とテンプレのキー集合が一致）
- (b) 実装
- コミット: `lib: スコア寄与から理由文を組み立てる`

## T7. `weather.js` — 泊まれる夜の判定

spec 3.3。`nightVerdict(day)` と `sleepingBagComfort(minTemp)`、`summarizeWeek(daily)`。

- (a) テスト: 境界値を1つずつ（-5.1/-5/-0.1/0/4.9/5℃、降水 39/40/69/70%、風 6.9/7/9.9/10 m/s）、複数条件が重なったとき厳しい側が勝つ、`null` 入り → `'unknown'`、Open-Meteo の実レスポンス形（配列の束）を `summarizeWeek` が日ごとに割る
- (b) 実装
- コミット: `lib: 週間予報から泊まれる夜を判定する`

## T8. `checklist.js` — 装備チェックリスト

`buildChecklist(site, { month, minTemp })` → カテゴリ付きの項目配列。レンタルがある設備は「（レンタルあり）」注記。氷点下なら防寒を追加。薪の現地販売が無く焚き火するなら「薪を持参」。

- (a) テスト: レンタルありの site で寝袋項目に注記が付く / 氷点下で防寒項目が増える / 薪販売なし＋焚き火可で「薪を持参」が入り、販売ありでは入らない / 項目 id が重複しない
- (b) 実装
- コミット: `lib: 装備チェックリストの生成`

## T9. `compare.js` — 比較表

`compareRows(a, b)` → `[{ label, a, b, winner: 'a'|'b'|null }]`。料金・アクセス・焚き火・設備・標高・営業期間。

- (a) テスト: 同値なら `winner: null` / 安いほうが勝つ / `transit: null` の側がアクセスで負ける / 行数が固定
- (b) 実装
- コミット: `lib: 2か所の比較表`

## T10. `favorites.js` — お気に入り

`toggle(ids, id)` / `load(store)` / `save(store, ids)`。`store` は `{ getItem, setItem }` を持つオブジェクトを引数で受け取る（localStorage を直接触らない）。壊れた JSON は空配列に倒す。

- (a) テスト: トグルで足りて消える / 壊れた JSON で例外を投げず `[]` / 保存した配列がそのまま復元される / 存在しない id を含んでも load が落ちない
- (b) 実装
- コミット: `lib: お気に入りの保存と復元`

## T11. `overpass.js` — OSM の正規化と重複除去

spec 3.4。`normalizeElements(elements)` と `mergeWithKnown(osmSites, knownSites)`。

- (a) テスト: `way` の `center` が使われる / 名前なしが落ちる / 収録済みから 399m は落ち 401m は残る（Haversine）/ 「氷川キャンプ場」と「氷川キャンプ場 」「氷川キャンプ場（奥多摩町）」が名前一致で落ちる / 空配列で落ちない
- (b) 実装（Haversine は同ファイル内の純粋関数）
- コミット: `lib: OSM データの正規化と収録済みとの重複除去`

## T12. データを 40 件へ拡張

T1 の10件に加え、檜原・青梅・あきる野・日の出・八王子・町田・府中・羽村・湾岸（若洲/城南島）・島しょ（大島・新島・式根島・神津島・三宅島・八丈島）を調べて足す。**1件ずつ一次情報で裏取りし `source` を書く。** 裏が取れなかったものは `verified: false` にして収録するか、落とす。

- (a) テスト: T1 のデータテストがそのまま全件に効く。加えて `balance` 前哨として「全エリアが1件以上」「`transit` 非 null が5件以上（車なし需要に応えられる）」
- (c) `pnpm test`
- コミット: `data: キャンプ場を40件規模へ拡張`

## T13. `balance.test.js` — 総当たり

spec 8節の3点。代表 criteria をコードで直積生成（車有無 × 焚き火3種 × 人数構成3種 × ペット × 予算3段 × 月4種）し、全組み合わせ × 全キャンプ場で回す。

- ハード制約違反が結果に一度も混ざらない
- 全キャンプ場が、ある criteria では1位を取れる（**死にデータが無い**）
- 上位3件が全部同点になる criteria が無い
- 摂動: criteria を1軸ずらしても1位が総入れ替えにならない（上位3件の重なりが1件以上）

落ちたらデータか重みを直す。**このテストを通すことが T5・T12 の答え合わせ。**

- コミット: `test: 全条件×全キャンプ場のバランス検証`
