# とまり火 (tomaribi) — 設計

東京のキャンプ場を、条件で絞りながら地図で眺め、同時に「今回はここ」を理由つきで名指ししてもらうサイト。

## 1. 何が起きるか

1. 画面を開くと、東京都全域の地図に収録キャンプ場のピンが立ち、右（狭い画面では下）に一覧が並ぶ。
2. 条件パネル（車の有無・焚き火・人数構成・ペット・予算・手ぶら可否・季節）を触ると、**その場でピンが減り、一覧が絞られる**。地図と一覧は同じ絞り込み結果を見ている。
3. 絞り込みの結果に対してスコア順の「提案カード」が出る。1位には理由が加点・減点の両方で並ぶ。
4. カードから詳細を開くと、アクセス（電車＋バス経路・最終バス時刻／車での距離）、料金、焚き火の可否、予約先リンク、そして **Open-Meteo の週間予報から作った「泊まれる夜」判定**と寝袋温度の目安が出る。
5. 2か所を選ぶと比較表になる。装備チェックリストは選んだ場所と季節・夜間気温から生成される。
6. 「もっと探す」を押すと Overpass API から OSM のキャンプ場を取得し、**自前データに無いものだけを「未確認」ピン**として地図に重ねる。提案順位には混ぜない。

## 2. データモデル

キャンプ場1件 = `src/lib/data/campsites.js` の1オブジェクト。追加は1件足すだけで全機能に載る。

```js
{
  id: 'kawai-camp',              // 一意・URL に出せる kebab
  name: '氷川キャンプ場',
  area: '奥多摩',                // 奥多摩 / 檜原 / 青梅・あきる野 / 高尾・八王子 / 多摩 / 湾岸 / 島しょ
  city: '西多摩郡奥多摩町',
  lat: 35.808, lon: 139.096,
  elevation: 340,                // m。夜間気温の補正と表示に使う
  price: { min: 1000, max: 2000, unit: 'per_person' }, // 1人あたり or サイト単位
  fire: { stand: true, ground: false, wood_sold: true },  // 焚き火台 / 直火 / 薪の現地販売
  facilities: { toilet: true, shower: true, rental: true, shop: true, power: false },
  allows: { solo: true, pet: true, family: true, group: true },
  car: { available: true, distance_km: 62, minutes: 90, parking_fee: 1500 },
  transit: {                      // 車なしで行けるか。null なら公共交通で到達不可
    from: '新宿',
    minutes: 105,
    legs: ['JR中央線・青梅線 奥多摩駅', '徒歩5分'],
    last_arrival: '20:30',        // その日のうちに現地に着ける最終到着時刻
  },
  season: { open: '04-01', close: '11-30' },   // null なら通年
  reservation: { required: true, url: 'https://...' },
  verified: true,                 // 一次情報（公式サイト・自治体ページ）で裏取り済み
  source: 'https://...',          // 裏取りに使ったURL
  note: '駅から徒歩で行ける数少ない河原サイト',
}
```

`verified: false` のデータを収録してよいが、提案カードには「未確認」バッジを必ず出す。

## 3. 中核の仕組み

### 3.1 ハード制約 → ソフトスコアの二段構え

条件（`Criteria`）に対して、まず**失格判定**を行う。失格はスコアで薄めない。

失格条件（いずれか1つでも該当したら候補から落とす）:

| 条件 | 失格になる場合 |
|---|---|
| `hasCar: false` | `transit` が `null`（公共交通で到達不可） |
| `pet: true` | `allows.pet === false` |
| `solo: true` | `allows.solo === false` |
| `fire: 'ground'`（直火したい） | `fire.ground === false` |
| `fire: 'stand'`（焚き火台） | `fire.stand === false` |
| `budget: N` | 1人あたり最低料金が N を超える |
| `month: M` | その月が営業期間外 |
| `tebura: true`（手ぶら） | `facilities.rental === false` |

残った候補に対して、加点・減点の重み付き和でスコアを出す。各項目は「寄与」として記録し、理由文の材料にする。

ソフト評価軸（0..1 に正規化した素点 × 重み）:

- **アクセスのしやすさ** — 車ありなら所要分、車なしなら電車＋バス所要分と最終到着時刻の余裕
- **焚き火の充実** — 直火可 > 焚き火台可、薪の現地販売あり
- **設備** — トイレ・シャワー・売店・電源・レンタル
- **静けさ / 賑やかさ** — `allows.group` と規模から。ソロ志向なら静かな側に加点、家族連れなら設備側に加点
- **価格の手頃さ** — 予算に対する余裕
- **標高と季節の相性** — 夏は高標高に加点、冬は低標高に加点

重みは `Criteria` によって変わる（車なしならアクセス重みを上げる、ソロなら静けさを上げる）。重みテーブルは `score.js` の1か所に集約する。

### 3.2 理由文

`reasons.js` は寄与の配列を受け取り、加点上位3件と減点上位2件をテンプレで文にする。テンプレは寄与の種類ごとに1つ。LLM は使わない。同じ入力なら常に同じ文。

### 3.3 天気（`weather.js`）

Open-Meteo の `daily` レスポンス（`temperature_2m_min`, `precipitation_probability_max`, `wind_speed_10m_max`, `weather_code`）を受け取り、日ごとに次を返す純粋関数:

- `verdict`: `'good' | 'ok' | 'tough' | 'no'`
  - `no`: 降水確率 70% 以上、または最大風速 15 m/s 以上、または最低気温 -5℃ 未満
  - `tough`: 降水確率 40% 以上、または最低気温 0℃ 未満、または風速 10 m/s 以上（風速は地上10mの日最大値。7 m/s では湾岸が常時該当して判定が意味を失うため引き上げた）
  - `ok`: 上記に該当せず、最低気温 5℃ 未満
  - `good`: それ以外
- `sleepingBagComfort`: 最低気温 - 5℃ を「快適使用温度がこれ以下の寝袋」として返す（就寝時の体感は予報最低気温より下がるため）
- データ欠損（`null`/`undefined`）は握りつぶさず `verdict: 'unknown'` を返す。

`weather.js` は fetch を含まない。取得は `src/ui/` 側の責務。

### 3.4 Overpass（`overpass.js`）

Overpass の JSON（`elements`）を受け取り、次を行う純粋関数:

- `node` / `way` / `relation` を lat/lon 1点に正規化（`center` があればそれを使う）
- 名前なしを落とす
- **自前データとの重複除去**: 収録済みキャンプ場から 400 m 以内、または名前が正規化一致（空白・記号・「キャンプ場」等の接尾辞を除去して比較）するものを落とす
- 残りに `verified: false`, `source: 'OpenStreetMap'` を付けて返す

## 5. UI の構成

- 上部: タイトルと条件パネル（チップ形式のトグル + スライダー2本 = 予算・出発時刻）
- 左（広い画面）: Leaflet 地図。ピンは「収録・提案上位」「収録・その他」「未確認(OSM)」の3種を色で分ける
- 右: 提案カードのリスト。上から順位。カードに理由（加点/減点）とバッジ（車不要 / 焚き火可 / 手ぶら / ペット可）
- カードのクリックで詳細パネル。詳細に週間天気と装備チェックリスト
- 「比較に追加」を2件まで。2件揃うと比較表を開くボタンが有効になる
- お気に入りは星アイコン。localStorage に id の配列で保存

狭い画面では地図と一覧をタブで切り替える。

## 6. 外部依存

| 依存 | 用途 | 失敗時 |
|---|---|---|
| Open-Meteo forecast API | 週間の最低気温・降水確率・風速 | 詳細パネルに「天気を取得できませんでした」と出し、他は動く |
| Overpass API | 「もっと探す」でOSMのキャンプ場 | ボタンにエラーを出す。自前データの機能は無傷 |
| Leaflet (CDN, ESM) | 地図描画 | 読み込み失敗時は地図領域にメッセージ。一覧と提案は動く |

いずれも**無いと壊れる作りにしない**。自前データだけで提案・絞り込み・比較・チェックリストが完結する。

## 7. 作らないもの

- ログイン・アカウント・サーバサイド（すべてブラウザ内で完結）
- 予約機能（公式サイトへのリンクのみ）
- 口コミ・レビュー投稿
- 乗換案内の動的経路検索（新宿からの代表経路を実データとして持つ）
- フェリー時刻表の動的取得（島しょは代表便を手データで持つ）
- 写真（外部アセットを持たない方針。地図と SVG アイコンで見せる）

## 8. 完了の定義

`pnpm test` が緑で、以下を保証していること。

1. **`balance.test.js` の総当たり**
   - 代表的な Criteria の全組み合わせ × 全キャンプ場で、**ハード制約に違反する候補が結果に一度も混ざらない**
   - 全キャンプ場が、ある Criteria では1位を取れる（**死にデータが無い**）
   - 上位3件のスコアが全部同点になる Criteria が無い（**並べる意味がある**）
2. `weather.js` が境界値（-5℃、0℃、降水70%、風速10m/s、欠損）で正しく分岐する
3. `overpass.js` が 400m 以内の重複と名前一致の重複を落とす
4. `access.js` が「車なしで到達不可」を正しく失格にする
5. ブラウザで console エラーがゼロ、絞り込み → 地図連動 → 提案 → 詳細 → 比較 → チェックリストが通しで動く
