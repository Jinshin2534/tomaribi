# とまり火 (tomaribi)

東京のキャンプ場を、条件で絞りながら地図で眺め、同時に「今回はここ」を理由つきで名指ししてもらうサイト。
車の有無・焚き火・景色・予算・季節などを選ぶと、地図のピンがその場で減り、一覧がスコア順に並び替わる。
理由は加点と減点の両方を出す（「＋薪の現地調達や直火」「−公共交通だと遠く、着く時刻が際どい」）。

## つかう

```
pnpm install
pnpm dev      # → http://localhost:5630
```

## テスト

```
pnpm test
```

## 作りの要点

**ハード制約 → ソフトスコアの二段構え。** 「車なしなのに公共交通で行けない」「休止中」「ペット不可」などは
候補から落とす（スコアで薄めない）。残った候補を7つの軸（アクセス・焚き火・設備・静けさ・価格・季節・景色）の
重み付き和で並べる。重みは条件で変わる（車なしならアクセスを重く、ソロなら静けさを重く）。
各軸の寄与を残しておき、それをそのまま理由文にする。LLM は使わず、同じ入力なら常に同じ結果になる。

**データは自前が主、OSM は従。** 焚き火の可否・料金・最終到着時刻は OpenStreetMap には無いので、
実在の29か所を1件ずつ調べて `verified` フラグと出典URL付きで持つ。「もっと探す」で Overpass API から
未収録のキャンプ場を取れるが、それは**未確認ピンとして地図に置くだけ**で、提案順位には混ぜない。
情報が欠けているものを1位にしない、というのが品質の線。

**balance.test.js が品質の要。** 全条件（車の有無 × 焚き火3種 × 人数4種 × 月4種 × 景色5種、
さらにペット・予算3段・手ぶら・遅い出発を重ねた計 3,360 通り）× 全キャンプ場を総当たりして、
①失格した場所が結果に一度も混ざらない ②どの場所も、ある条件では一覧に出る ③上位3位に入れない場所は
「同エリアに、あらゆる条件で自分以上の場所が実在する」場合に限る ④上位が総入れ替えになるのは
候補集合そのものが変わったときだけ、を保証する。データを足したら必ずここを通す。

この総当たりが、実際に「景色」の軸が無いことを見つけた（島や湾岸のキャンプ場が、どんな条件でも
一度も提案されない状態だった）。

## 意図的な制約

- ログイン・アカウント・サーバは持たない。すべてブラウザ内で完結する（お気に入りは localStorage）
- 予約はしない。公式サイトへのリンクだけ
- 口コミ・レビュー投稿はない
- 乗換案内の動的検索はしない。新宿からの代表経路を実データとして持つ
- 写真を持たない。地図と文字と色だけで見せる
- 島しょは `car.available: false` にしている。フェリーに車を載せることはできるが、
  「車で行く」条件の人に勧める選択肢ではないため

## データについて

`src/lib/data/campsites.js` に1件1オブジェクトで入っている。追加は1件足すだけで、絞り込み・スコア・
地図・比較・チェックリストのすべてに載る。

`verified: true` が保証するのは「場所・アクセス経路・料金水準・焚き火の可否」を一次情報で確認したこと。
設備の細目は公式表記が見つからなければ `false` に倒している（「無いと言って現地にあった」は許容し、
「あると言って無かった」は許容しない）。`verified: false` の場所は画面に**未確認**バッジが出る。
料金と営業期間は変わるので、最終的な確認は各カードの公式リンクから。

## 外部依存

| 依存 | 用途 | 落ちたとき |
|---|---|---|
| Open-Meteo | 週間の最低気温・降水確率・風速 | 詳細に「天気を取得できませんでした」。他は動く |
| Overpass API | 「もっと探す」でOSMのキャンプ場 | ボタンにエラー。自前データの機能は無傷 |
| Leaflet (CDN) | 地図 | 地図欄にメッセージ。一覧と提案は動く |

どれも無いと壊れる作りにはしていない。
